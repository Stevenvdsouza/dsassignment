📖 How It Works ▼

A circular queue (ring buffer) uses a fixed-size array whose end wraps around to the beginning, forming a logical circle. Unlike a plain linear queue — where freed head slots are wasted and the array gradually "slides" toward the end — a circular queue reuses every slot.

The Key Formula

Every pointer advance uses modular arithmetic:

rear  = (rear  + 1) % capacity   // move rear forward; wraps slot 4 → slot 0
front = (front + 1) % capacity   // move front forward after each dequeue

Why not a simple array queue?

In a naive array queue, dequeuing either shifts every remaining element left — O(n) — or leaves dead space at the front. After capacity enqueue+dequeue cycles the rear pointer reaches the end and the queue appears full, even though the front slots are free. The circular approach reclaims those slots in O(1).

State Variables

  • array[0..capacity-1] — fixed-size backing store
  • front — index of the oldest element (next to be removed)
  • rear — index of the newest element (most recently added)
  • count — number of current elements (distinguishes full from empty when front == rear)
💻 Pseudocode ▼
ENQUEUE(ticket)
if count == capacity:
    raise OverflowError
rear  ← (rear + 1) mod capacity
array[rear] ← ticket
count ← count + 1
DEQUEUE()
if count == 0:
    raise UnderflowError
ticket ← array[front]
array[front] ← null
front ← (front + 1) mod capacity
count ← count - 1
return ticket
FRONT()
if count == 0:
    raise Error
return array[front]
REAR()
if count == 0:
    raise Error
return array[rear]
IS_EMPTY()
return count == 0
IS_FULL()
return count == capacity
⏱ Time & Space Complexity ▼
Operation Time Aux Space Reason
enqueue() O(1) O(1) One modular addition + one array write
dequeue() O(1) O(1) One array read + one modular addition
front() O(1) O(1) Direct index access via front pointer
rear() O(1) O(1) Direct index access via rear pointer
isEmpty() O(1) O(1) Single comparison: count == 0
isFull() O(1) O(1) Single comparison: count == capacity
Total Space O(n) n = capacity — fixed backing array

All six operations are constant time — only simple arithmetic and direct array indexing, no loops or shifting.

⚖️ Why FIFO is Fair ▼
  • Arrival order preserved — the first customer to raise a ticket is always served first. Nobody skips the line.
  • No starvation — every ticket will eventually reach the front; later arrivals cannot block earlier ones.
  • Predictable wait times — a customer knows they must wait for exactly count tickets ahead of them, making the system transparent.
  • Equal treatment — in a basic FIFO queue every ticket is equal; priority requires a separate priority-queue structure.
  • Real-world analogy — printer spoolers, CPU round-robin scheduling, network packet buffers, and supermarket checkouts all rely on FIFO fairness.
⚠️ Limitations & Real-World Considerations ▼
  • Fixed capacity — when all 5 slots are occupied, new ticket requests are rejected (overflow). In a real call centre tickets must not be silently discarded; the caller must be informed or placed in a secondary queue.
  • No dynamic resizing — unlike a linked-list queue, a circular array queue cannot grow at runtime. Burst traffic requires a larger pre-allocated buffer or a growable queue backed by a dynamic array.
  • No priority support — FIFO treats all tickets equally. VIP or critical escalations would need a separate priority queue structure.
  • Not thread-safe — concurrent enqueue/dequeue would need mutex locks or lock-free atomic operations in a multi-agent environment.
  • Memory always allocated — even when empty the full-size array exists, wasting memory compared to a linked-list queue that only allocates nodes as needed.
